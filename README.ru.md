# XInput → DualShock 4 Bridge

![Platform](https://img.shields.io/badge/platform-RP2040-blue)
![Language](https://img.shields.io/badge/language-C11-lightgrey)
![License](https://img.shields.io/badge/license-MIT-green)

**Bluetooth-геймпад Xbox на PlayStation 4. Без ПК, без софта, на двух Raspberry Pi Pico.**

Pico W принимает геймпад по Bluetooth и выдаёт состояние кнопок и стиков в GPIO и PWM.
Обычный Pico с прошивкой GP2040-CE читает эти линии и прикидывается DualShock 4 по USB.
Консоль видит обычный проводной DS4.

## Зачем

PS4 принимает по USB только аутентифицированные контроллеры DualShock 4. Геймпад Xbox
подключить напрямую нельзя, а готовые решения — это либо ПК с Remote Play, либо закрытые
платные адаптеры.

Здесь вся трансляция происходит в железе на деталях примерно за 1000 ₽. Сигнальный путь
полностью открытый: любую линию можно померить мультиметром или логическим анализатором.

> **Про название.** XInput — это USB-API Windows. По Bluetooth геймпад Xbox отдаёт обычный
> HID, и именно его разбирает Bluepad32. Название репозитория оставлено для узнаваемости.

## Как это работает

```
                    Bluetooth (HID)
   ┌──────────────┐   классик + BLE   ┌────────────────────┐
   │ Геймпад Xbox │ ────────────────► │ Pico W             │
   └──────────────┘                   │ Bluepad32 + BTstack│
                                      └─────────┬──────────┘
                                                │
                        18× GPIO (активный LOW) │
                        4× PWM 488 кГц → RC     │
                                                ▼
                                      ┌────────────────────┐
                                      │ Pico               │
                                      │ GP2040-CE (PS4)    │
                                      └─────────┬──────────┘
                                                │ USB HID (DS4)
                                                ▼
                                      ┌────────────────────┐
                                      │ PlayStation 4      │
                                      └────────────────────┘
```

| Звено | Что передаётся | Как |
|---|---|---|
| Геймпад → Pico W | HID-репорты | Bluetooth, стек BTstack + Bluepad32 |
| Pico W → Pico (кнопки) | 18 линий, 3.3 В | прямой провод, **LOW = нажато** |
| Pico W → Pico (стики) | 4 напряжения 0…3.3 В | 8-битный PWM + RC-фильтр → АЦП |
| Pico → PS4 | репорт DS4 | USB HID, опрос 1 кГц |

Оба микроконтроллера питаются от 3.3 В, поэтому **согласование уровней на цифровых линиях
не нужно** — только общая земля. Вся аналоговая обвязка сводится к четырём RC-фильтрам,
которые превращают PWM в постоянное напряжение.

### Что делает прошивка

- читает геймпад через кастомную платформу Bluepad32 (`bridge_platform.c`);
- раскладывает кнопки по 18 GPIO, оси — по 4 каналам PWM;
- при потере связи отпускает все кнопки и возвращает стики в центр;
- при старте выдерживает паузу, чтобы GP2040-CE корректно откалибровал оси.

## Железо

### Состав

| Поз. | Кол-во | Деталь | Номинал | Назначение |
|---|---|---|---|---|
| U1 | 1 | Raspberry Pi Pico W | RP2040 + CYW43439 | Bluetooth-приёмник |
| U2 | 1 | Raspberry Pi Pico | RP2040 | GP2040-CE, USB-устройство |
| R1–R4 | 4 | Резистор | 10 кОм 1 % | RC-фильтр |
| C1–C4 | 4 | Конденсатор | 100 нФ X7R | RC-фильтр |
| D1–D2 | 2 | Диод Шоттки | BAT54 / 1N5817 | развязка питания |
| R5–R22 | 18 | Резистор (опц.) | 100 Ом | защита цифровых линий |


### Кнопки: Pico W → GP2040-CE

Все линии активны по нулю: `LOW` — нажато, `HIGH` — отпущено.

| GPIO | Кнопка DS4 | Константа Bluepad32 |
|---|---|---|
| GP2 | Cross (✕) | `BUTTON_A` |
| GP3 | Circle (○) | `BUTTON_B` |
| GP4 | Square (□) | `BUTTON_X` |
| GP5 | Triangle (△) | `BUTTON_Y` |
| GP6 | L1 | `BUTTON_SHOULDER_L` |
| GP7 | R1 | `BUTTON_SHOULDER_R` |
| GP8 | L2 (цифровой) | `BUTTON_TRIGGER_L` |
| GP9 | R2 (цифровой) | `BUTTON_TRIGGER_R` |
| GP10 | L3 | `BUTTON_THUMB_L` |
| GP11 | R3 | `BUTTON_THUMB_R` |
| GP12 | Share / Select | `MISC_BUTTON_BACK` |
| GP13 | Options / Start | `MISC_BUTTON_HOME` |
| GP14 | PS / Guide | `MISC_BUTTON_SYSTEM` |
| GP15 | Touchpad click | `MISC_BUTTON_CAPTURE` |
| GP16 | D-Pad Up | `DPAD_UP` |
| GP17 | D-Pad Down | `DPAD_DOWN` |
| GP18 | D-Pad Left | `DPAD_LEFT` |
| GP19 | D-Pad Right | `DPAD_RIGHT` |

Лицевые кнопки маппятся **по физическому расположению**, а не по названию: нижняя кнопка
Xbox (A) становится Cross, правая (B) — Circle и так далее. Играть можно не задумываясь.

### Стики: PWM → RC → АЦП

| GPIO Pico W | PWM slice / канал | Фильтр | Пин Pico | Ось | Поле |
|---|---|---|---|---|---|
| GP21 | 2 / B | 10 кОм + 100 нФ | GP26 (ADC0) | Left X | `axis_x` |
| GP22 | 3 / A | 10 кОм + 100 нФ | GP27 (ADC1) | Left Y | `axis_y` |
| GP26 | 5 / A | 10 кОм + 100 нФ | GP28 (ADC2) | Right X | `axis_rx` |
| GP28 | 6 / A | 10 кОм + 100 нФ | GP29 (ADC3) | Right Y | `axis_ry` |

Каждая ось сидит **на своём PWM-слайсе**, поэтому у каналов независимая скважность.
GP23, GP24, GP25 и GP29 на Pico W не используются — они заняты беспроводным чипом CYW43.

### Питание

Обе платы питаются от одной шины 5 В через диодное ИЛИ на диодах Шоттки:

- USB-разъём PS4 → VBUS платы Pico → диод → VSYS платы Pico W;
- после диода на VSYS приходит около 4.7 В — это в пределах допустимых 1.8…5.5 В;
- обратное питание исключено, можно включать любой из двух USB-разъёмов;
- суммарное потребление меньше 100 мА, порта консоли хватает с запасом.

Отдельный блок питания не нужен: **адаптер целиком питается от USB самой PS4.**

### Нюансы разводки

- **Конденсатор ставить вплотную к выводу АЦП.** Он работает как резервуар заряда для
  схемы выборки-хранения RP2040, поэтому 10 кОм сопротивления источника не дают ошибки
  измерения.
- **Земля обязательно общая**, иначе «плавающий» ноль испортит и цифры, и аналог.
- **GP29 на оригинальном Pico подключён к делителю VSYS.** Он подмешивает смещение
  и слегка сжимает диапазон правой оси Y. Калибровка GP2040-CE это компенсирует, но при
  разводке своей платы стоит свериться со схемой Pico.

## Почему именно такие номиналы

**Частота PWM.** `clkdiv = 1.0`, `wrap = 255`, тактовая 125 МГц:

```
f_pwm = 125 МГц / 256 = 488.28 кГц
```

**Фильтр.** R = 10 кОм, C = 100 нФ:

```
τ   = R·C = 1.0 мс
f_c = 1 / (2π·R·C) = 159 Гц
```

Несущая в три тысячи раз выше среза, подавление — около **−70 дБ**.

**Пульсации.** Худший случай при скважности 50 %:

```
V_ripple ≈ V·D·(1−D) / (f·R·C) = 3.3 · 0.25 / (488281 · 0.001) ≈ 1.7 мВ p-p
```

Это примерно 2 младших разряда 12-битного АЦП и **восьмая часть одного шага PWM**
(3.3 В / 255 = 12.9 мВ). То есть фильтр не «съедает» полезную точность.

**Время установления.** До точности одного шага DS4 (0.4 %) — около 5.5 τ ≈ **5.5 мс**.
Именно поэтому в прошивке есть стартовая пауза 3 секунды: конденсаторы должны дойти
до середины диапазона до того, как GP2040-CE начнёт автокалибровку.

**Почему 8 бит достаточно.** В USB-репорте DualShock 4 оси тоже 8-битные. Разрешение
самодельного ЦАП совпадает с разрешением целевого протокола — гнаться за 12 битами незачем.

## Сборка и прошивка

### Что понадобится

- `arm-none-eabi-gcc`, `cmake` ≥ 3.13, `python3`
- [pico-sdk](https://github.com/raspberrypi/pico-sdk)
- [Bluepad32](https://github.com/ricardoquesada/bluepad32)

### Сборка

```bash
git clone --recursive https://github.com/AV4KADA/xinput2ds4.git
cd xinput2ds4

export PICO_SDK_PATH=/path/to/pico-sdk

cmake -S firmware/bridge -B build -DPICO_BOARD=pico_w
cmake --build build -j4
```

> В `CMakeLists.txt` обязательно должны быть определены `ENABLE_BLE` и `ENABLE_CLASSIC`.
> Без них `btstack_config.h` намеренно останавливает сборку через `#error`.

### Запись

1. Зажать BOOTSEL на Pico W, подключить USB.
2. Скопировать `build/bridge.uf2` на диск `RPI-RP2`.

```bash
cp build/bridge.uf2 /media/$USER/RPI-RP2/
```

Готовые файлы лежат в [Releases](https://github.com/AV4KADA/xinput2ds4/releases).

## Настройка GP2040-CE

1. Прошить официальный `.uf2` GP2040-CE на **обычный Pico**.
2. Зажать нужную кнопку при старте, чтобы войти в веб-конфигуратор, открыть
   `http://192.168.7.1`.
3. **Settings → Input Mode:** выбрать `PS4` как режим по умолчанию.
4. **Pin Mapping:** назначить входы кнопок строго по таблице выше.
5. **Analog:** включить ADC0…ADC3 и запустить калибровку. Мост при этом должен быть
   включён, а стики геймпада — отпущены.
6. Либо просто импортировать готовый конфиг
   [`firmware/gp2040ce/board-config.bak`](firmware/gp2040ce/).

> **Аутентификация PS4.** Режим PS4 в GP2040-CE требует данных аутентификации от собственного
> DualShock 4, иначе консоль отключает контроллер примерно через 8 минут. Следуй официальной
> документации GP2040-CE. **Ключи и файлы аутентификации в этом репозитории не хранятся.**

## Подключение геймпада

1. Подать питание на адаптер.
2. Светодиод Pico W горит во время инициализации (около 3 секунд) и гаснет, когда начинается
   поиск устройств.
3. Перевести геймпад в режим сопряжения.
4. После подключения ввод сразу идёт на консоль.

Клавиатуры отфильтровываются на этапе обнаружения по классу устройства (COD), чтобы
случайный Bluetooth-девайс не занял слот.

> Ключи сопряжения сейчас стираются при каждой загрузке — после выключения питания геймпад
> нужно спарить заново. Это осознанное поведение, см. [планы](#планы).

## Отладка

**Логи.** UART 115200, уровень `Info`. Прошивка печатает состояние только когда оно ненулевое,
чтобы не забивать канал в покое:

```
btns=00000001 misc=00 dpad=00 LX=-12 LY=8 RX=0 RY=0
```

**Проверка аналога мультиметром.** На конденсаторе фильтра:

| Положение стика | Ожидаемое напряжение |
|---|---|
| отпущен | ≈ 1.65 В |
| край влево / вниз | ≈ 0 В |
| край вправо / вверх | ≈ 3.3 В |

**Проверка без консоли.** Переключить GP2040-CE в режим XInput, подключить к ПК и открыть
любой gamepad tester — видно все кнопки и оси.

**Важно про логи в релизе.** Строка лога — это ~70 символов, на 115200 бод это около 6 мс.
Для замеров задержки и для боевой прошивки логи стоит выключить
(`CONFIG_BLUEPAD32_LOG_LEVEL 0`).

| Звено | Значение | Откуда |

| Несущая PWM | 488.28 кГц | расчёт |
| Пульсации фильтра | ≈ 1.7 мВ p-p | расчёт |
| Установление оси до 1 шага DS4 | ≈ 5.5 мс | расчёт |
| Опрос USB (GP2040-CE) | 1 мс | настройка прошивки |
| Интервал Bluetooth-соединения | TBD | измерение |
| **Сквозная задержка ввода** | **TBD** | измерение |

Основной вклад дают Bluetooth-звено и RC-фильтр. Цифровые кнопки идут мимо фильтра, поэтому
нажимаются быстрее, чем двигаются стики.

## Ограничения

Честный список того, что сейчас работает не идеально:

- **Нужна аутентификация PS4** для сессий дольше ~8 минут.
- **L2 и R2 цифровые.** Используются флаги `BUTTON_TRIGGER_*`, аналоговые значения
  `brake` / `throttle` пока не задействованы.
- **Оси не доходят до краёв.** Формула `128 + axis·127/512` даёт диапазон PWM 1…254 вместо
  0…255 — теряется около 0.8 % с каждого края. Калибровка GP2040-CE это скрывает.
- **Ключи сопряжения стираются при каждом старте** (`uni_bt_del_keys_unsafe()`), геймпад
  приходится спаривать заново.
- **Активным должен быть только один геймпад.** Bluepad32 настроен на 4 устройства, но все
  они пишут в одни и те же GPIO.
- **Не передаются:** вибрация, гироскоп, акселерометр, координаты тачпада.
